## Descripcion

Agrega continuidad al chatbot del portal ciudadano: el ciudadano puede retomar
el flujo guiado de reclamo o trámite después de loguearse, e iniciar directamente
un trámite o reclamo guiado desde su portal sin pasar por el chat público.

## User Story

```
Como ciudadano (anónimo o logueado) quiero poder iniciar un reclamo o trámite
a través del chat del portal y, si durante el proceso necesito registrarme o
iniciar sesión, poder retomar el mismo chat en el punto exacto donde lo dejé,
para no tener que volver a empezar desde cero.
```

## Criterios de aceptacion

- [x] El ciudadano anónimo puede iniciar y completar un reclamo sin datos de contacto
- [x] Al intentar iniciar un trámite sin login, el bot muestra link de login/registro con `?next=` a la conversación
- [x] Al loguearse usando ese link, el bot envía automáticamente el siguiente mensaje (lista de tipos) al cargar la página
- [x] La conversación anónima NO se vincula al ciudadano ni aparece en "mis consultas"
- [x] Dentro del portal logueado existe "Hacer un reclamo" e "Iniciar un trámite" en Mis Consultas, que disparan el bot guiado
- [x] El bot guiado es el único camino — no hay formulario directo
- [x] Si el bot no puede completar la gestión, ofrece derivar a operador

## Decisiones tecnicas

**Flag `reactivado` en `flujo.datos`:** para evitar que el endpoint de reactivación
envíe el mensaje dos veces si el ciudadano recarga la página. El flag se persiste
en la base antes de generar el mensaje del bot.

**Reactivación directa a lista de tipos:** al reactivar post-login, en lugar de
mostrar un mensaje introductorio genérico, el bot va directo a `_preparar_seleccion_tipo`
para no obligar al ciudadano a hacer otro paso innecesario.

**`success: True` cuando no hay flujo pendiente:** el endpoint retorna `success: true,
finalizado: true` (en vez de `success: false`) para distinguir "no había nada que hacer"
de un error real.

**Sin vinculación de conversación anónima:** la conversación iniciada como anónima
no se vincula al ciudadano al loguearse. Queda como conversación transitoria; el
historial del portal solo muestra conversaciones con `ciudadano_usuario` asignado.

## Limitaciones conocidas / deuda tecnica

- El bot no recolecta campos dinámicos de trámite (`CampoDinamicoTramite`).
- No hay notificación al ciudadano cuando cambia el estado de su trámite/reclamo.
- Adjuntos durante el flujo del bot no están soportados.
