## Descripcion

El editor visual de flujos evoluciona desde un canvas basico a una herramienta mas cercana a la operatoria real. La pantalla ahora muestra estado de versiones e instancias activas, y el panel de propiedades permite configurar visualmente el contrato `config.formulario` de un nodo `accion_humana`. El resultado es un editor mas claro para operadores/configuradores y mejor alineado con el runtime real del modulo.

## User Story

```
Como usuario con rol programaConfigurar quiero configurar visualmente el formulario de cada paso humano del flujo
para guardar y publicar un circuito operativo sin depender de JSON manual
```

## Criterios de aceptacion

- [x] La pantalla del editor muestra resumen operativo del programa, estado de versiones e instancias activas
- [x] El panel de propiedades de un nodo `accion_humana` permite elegir tipo de formulario tipado
- [x] El editor soporta configuracion visual de `boolean_decision`, `text_input` y `choice_select`
- [x] `config.formulario` se persiste al guardar borrador y se reconstruye al volver a abrir el editor
- [x] Los nodos `accion_humana` muestran visualmente que tienen formulario configurado
- [x] La validacion frontend revisa el contrato del formulario antes de publicar
- [x] Las salidas booleanas guiadas ayudan a configurar `true/false` sobre el campo correcto
- [x] El bundle compilado usado por Django queda regenerado en `static/flujos/dist/`

## Decisiones tecnicas

- **El editor usa el mismo contrato del backend:** en vez de inventar una capa intermedia, React edita directamente `config.formulario` y lo round-tripea con la definicion oficial del flujo.
- **Validacion temprana en frontend:** los errores de formularios tipados aparecen antes del request de publicar, pero la validacion final sigue viviendo en backend.
- **Shell mas operativa sin rehacer la app:** se mejoro la pagina Django que contiene el bundle para dar contexto al usuario sin convertir el editor en una SPA completa.

## Limitaciones conocidas / deuda tecnica

- El smoke test real del round-trip completo editor/backend sigue pendiente de automatizacion.
- La compilacion del bundle sigue siendo manual con `npm run build` antes de desplegar cambios del editor.
- El panel hoy cubre solo tres tipos de formulario y no expone todavia contratos mas avanzados como roles por paso o formularios compuestos.

## Cambios respecto a version anterior

La v1.0 permitia construir nodos, transiciones, nombres y condiciones simples. La v1.1 vuelve al editor parte del contrato operativo real del modulo: suma contexto de versiones en la pantalla, deja configurar `config.formulario` visualmente, refleja esa configuracion en el nodo y valida el formulario antes de publicar.
